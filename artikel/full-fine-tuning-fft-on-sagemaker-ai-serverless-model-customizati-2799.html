Fine-tuning is the process of continuing to train a pretrained large language model (LLM) on a manufacturer’s own data so it adapts to a specific domain, task, or style rather than relying on general-purpose knowledge alone. For businesses, the value is twofold. A fine-tuned model delivers measurably better accuracy on domain-specific work while reducing costs: a smaller specialized model can match or exceed a frontier model on your task at a fraction of the per-token inference price. Those savings compound across millions of requests. Fine-tuning has therefore become an essential process for businesses looking to get more value from LLMs at lower costs.

According to recent reports, parameter-efficient fine-tuning (PEFT) methods like Low-Rank Adaptation (LoRA) have emerged as a practical solution for fine-tuning LLMs to downstream tasks, reducing GPU capacity requirements by updating only a small subset of LLM parameters. LoRA aims to strike a balance between efficiency and expressiveness, however, the low-rank nature of the weight update inherently limits the representation power of LoRA fine-tuned models, potentially compromising performance on complex tasks. This trade-off hampers the ability of LoRA methods to capture complex patterns needed for diverse tasks. To address these challenges, Full Fine-Tuning (FFT) updates model parameters simultaneously, overcoming the low-rank limitations so LLMs can fully absorb complex domain-specific knowledge.

Amazon SageMaker AI Serverless Model Customization now supports Full Fine-Tuning (FFT), so you can achieve superior model quality without managing infrastructure. There is no GPU provisioning, cluster setup, or distributed-training configuration required. In this post, we explore when and where FFT consistently outperforms LoRA across key benchmarks, examine the spectral properties of model weight matrices that explain this quality gap, provide practical hyperparameter tuning guidelines backed by controlled experiments using SageMaker AI Serverless Model Customization, and show you how to get started with FFT on SageMaker AI.

Model customization types like LoRA reduce trainable parameters by freezing the pre-trained model’s weights and injecting small, separate pairs of replacement matrices (called low-rank matrices) into the model layers. This works well for simple adaptations, but the low-rank structure inherently limits the representation power of the fine-tuned model. As tasks grow more complex and datasets scale beyond tens of thousands of examples, LoRA hits an accuracy plateau where increasing rank (and thus trainable parameters) fails to bridge the accuracy gap with standard fine-tuning. This plateau reveals that the performance gap isn’t simply because of fewer parameters. It’s caused by rank deficiency itself. The low-rank update can’t capture the full complexity of the weight changes needed for deep task adaptation.

According to recent reports, however, for complex tasks and domains where large, good-quality datasets exist, full-rank fine-tuning excels by updating model parameters simultaneously. FFT modifies the model’s weight matrix uniformly, using the full representational capacity of the model’s weight matrices rather than restricting updates to a small subspace, and without introducing the abrupt, localized distortions characteristic of low-rank methods. The result is stronger model convergence, better activation alignment across model layers, and a model that faithfully captures both the target task distribution and the richness of its pre-trained knowledge. PRIMECODE is a custom scorer evaluation that measures how closely the model’s generated code matches reference solutions using deterministic text-similarity metrics: BLEU (n-gram precision), ROUGE-1/2/L (recall-oriented overlap), and F1 (precision-recall balance). We used PRIMECODE as our primary metric for surface-level code quality because it quantifies how well the model has learned the coding patterns, formatting conventions, and implementation style present in the training data. In full fine-tuning, the learning rate controls how aggressively every weight is updated. Unlike LoRA, where only small adapter matrices change, an FFT learning rate that is too high permanently overwrites pretrained knowledge. In our experiments, the following LR × dataset-size risk map demonstrates that an LR of 2e-5 on a large dataset (over 100 thousand) was the safe zone.

Figure 9: Learning rate and dataset-size risk map for full fine-tuning.

Sources indicate that epoch count in FFT is fundamentally a forgetting question, not a loss-curve question. Training loss will keep falling and your held-out validation will look healthy because it shares a distribution with training data, but capabilities on everything you didn’t train on quietly degrade. The LLM-as-Judge correctness score rose to 90.0 percent at 3 epochs, and extending beyond 3 epochs degraded every variant we experimented with.

Batch size determines how many examples contribute to each gradient step. At a fixed learning rate, smaller batches produce more noisy updates that behave much like a higher learning rate, increasing forgetting risk. Larger batches reduce noise but also reduce the number of optimization steps, potentially underfitting.

Figure 10: Effect of global batch size on model quality.

In a recent development, FFT modifies every parameter in the model, including the parameters that encode general knowledge acquired during pre-training. When fine-tuning pushes these parameters too aggressively toward a narrow domain, the model can “forget” its broader capabilities, a phenomenon known as catastrophic forgetting. We tested for this systematically using MMLU, measuring general knowledge retention across all our fine-tuning configurations. A baseline configuration with warmup=5 percent, batch size 8, and LR=2e-5 best preserved general knowledge (MMLU), as shown in the following figure.

Figure 11: MMLU general-knowledge retention across hyperparameter configurations.

In a recent development, hence, it is key to note that FFT isn’t universally superior to LoRA, and its effectiveness is extremely sensitive to hyperparameter choices. For example, in our experiments, both FFT and LoRA underperformed the base model on MATH exact match, underscoring the challenge of preserving reasoning capabilities during domain-specific fine-tuning. Aggressive learning rates (LR ≥ 5e-5) in FFT proved particularly destructive, causing MATH scores to plummet to 2–3 percent and MMLU accuracy to drop to 3.6 percent, clear evidence of catastrophic forgetting. Additionally, LoRA slightly outperformed FFT on the LLM-as-Judge metric (81.5 percent compared to 79.5 percent), demonstrating that parameter-efficient methods can still hold an edge on subjective quality assessments. These findings reinforce that the choice between FFT and LoRA should be guided by careful experimentation, dataset characteristics, and a clear understanding of the trade-offs involved.
