Tech Report: Amazon Bedrock AgentCore harness adds Strands harness defaults, built-in tools, and lifecycle hooks

📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

When building an AI agent, selecting a model is only the first step. The agent still needs tools, instructions for finishing the job, a way to manage context growth in long sessions, and guardrails before it executes any consequential actions, like issuing a refund.

We are upgrading Amazon Bedrock AgentCore harness to use Strands harness, our open-source agent harness, released earlier this year, available under an Apache 2.0 license. AgentCore harness also introduces lifecycle hooks, so you can apply your own deterministic checks and notifications at defined points in the agent loop.

With this upgrade, agents that rely on the managed defaults get a recommended model, a task-oriented system prompt, automatic prompt caching (initially for Anthropic models on Amazon Bedrock), and proactive context management. They also get additional built-in tools for planning, web retrieval, filesystem access, context offloading, and task delegation. This gives agents greater capabilities during long tasks, allowing them to keep track of subtasks, reduce context window usage, and delegate work. With hooks, you can transform non-deterministic AI behavior into predictable, safe, and governed workflows by running deterministic code at specific lifecycle checkpoints.

Industry observers note that there’s no upcoming resource type or integration to adopt. You automatically get both updates in the AgentCore harness you already use.

In a recent development, strands harness provides an assembled agent foundation with recommended instructions, tools, and context management. Amazon Bedrock AgentCore harness operates that foundation as a managed AWS service. The result is a production-grade default agent that doesn’t require you to assemble and operate the harness or its infrastructure yourself.

You do not need to provision compute, bundle and host the agent loop, manage session scaling, or operate tool-execution infrastructure. Each session runs in a secure, kernel-isolated microVM in AgentCore runtime, a capability of Amazon Bedrock AgentCore, with managed compute, scaling, and high availability.

AgentCore achieves this by connecting the harness to the services required for production agents, including session persistence, streaming responses, usage metadata, observability, AgentCore memory, Identity, Gateway, Browser, Code Interpreter, and customer-provided containers. You retain control over the model, instructions, tools, permissions, and lifecycle policies while AgentCore manages the underlying execution environment.

Harness manages its defaults so that agents using them receive the current AgentCore recommended experience as models, instructions, context management, and built-in capabilities improve.

With lifecycle hooks, you can run your own deterministic code at defined points in the agent loop. For example, an AWS Lambda function can allow or deny a request or a tool call, and an Amazon Simple Notification Service (Amazon SNS) topic or Amazon EventBridge event bus can receive a notification to record activity or start an asynchronous workflow.

It has been revealed that only Lambda hooks can change the agent loop. They run synchronously and return allow or deny, with an optional reason. SNS and Amazon EventBridge hooks are notifications and don’t block the agent loop.

When the function denies the call, the harness skips the refund and the agent continues, so it can tell the customer that the request was escalated. Each decision also appears in the InvokeHarness response stream as a hookEvent:.

Sources indicate that hooks also apply to subagents. When the agent delegates a task, each tool call the subagent makes runs through the same beforeToolCall and afterToolCall hooks, so delegation can’t bypass your refund policy. The invocation-level hooks (beforeInvocation, afterInvocation) run once for the whole invocation.

You configure hooks with CreateHarness or UpdateHarness. If a Lambda function times out or returns an error, the hook applies its failureMode, which defaults to deny. For timeouts, payload fields, and context limits, see Lifecycle hooks in the Amazon Bedrock AgentCore Developer Guide.

Recent findings suggest that on November 11, AgentCore harness began rolling out the Strands harness-backed experience to new and existing harnesses. No customer action is required.

Configuration you explicitly provide remains unchanged. Harnesses that omit the model, system prompt, or truncation configuration, or use allowedTools: ["*"], receive the upgraded managed defaults.

If your application requires fixed behavior or a fixed capability boundary, configure those settings explicitly.
