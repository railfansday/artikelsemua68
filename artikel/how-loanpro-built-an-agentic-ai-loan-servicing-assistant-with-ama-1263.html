Have you ever wondered what the experience is like for the person on the other end of the phone when you call your bank for support? When a borrower calls a lender, the answering agent must pull account data from dozens of fields, transaction histories, and workflow queues to orient themselves before they can help the borrower. All the while, the clock runs. Assembling that context by hand means longer calls, inconsistent service quality, and agent frustration. A loan servicing assistant built on agentic AI changes that.

LoanPro, the operating system for modern lenders, set out to change that. Working with AWS Partner AllCloud and the AWS Generative AI Innovation Center, LoanPro built a multi-agent AI assistant that gives servicing agents immediate access to synthesized borrower context and actionable next-step recommendations. Early results show customer call times reduced by up to 15 percent, according to AllCloud’s published case study.

Industry observers note that in this post, we walk through the business challenge, the agentic AI architecture built on Amazon Bedrock and Amazon Bedrock AgentCore, and the outcomes LoanPro achieved. Amazon Bedrock is a fully managed service that offers a choice of high-performing foundation models from leading AI companies through a single API, along with the capabilities you need to build generative AI applications with security, privacy, and responsible AI.

Sources indicate that loanPro is a modern, API-first lending and credit platform that automates the entire loan lifecycle from origination to payoff. Founded in 2015, LoanPro serves as the system of record for lenders of every type: fintechs, banks and credit unions, and corporates that offer lending as a value-added service. According to LoanPro, the platform serves over 450 lenders, with loans managed on its platform reaching about 31 percent of US households. The platform powers loan management at enterprise scale across the financial services industry.

LoanPro isn’t a lender. It’s the operating system that lenders run on. That distinction matters because LoanPro’s AI strategy is designed to benefit the institutions it serves across the platform, not a single lending operation.

In a recent development, with the AWS Generative AI Innovation Center, LoanPro partnered with AllCloud to design and build a multi-agent AI assistant using Amazon Bedrock. The assistant runs on Anthropic’s Claude Sonnet 5.5, Claude Haiku 5.5, and Claude Opus 5.5 on Amazon Bedrock (see Models at a glance in Amazon Bedrock). Model availability varies by AWS Region. For model availability by Region, refer to Regional availability by models in Amazon Bedrock. It’s orchestrated with Amazon Bedrock AgentCore, a platform to build, connect, and optimize agents at scale, with any framework or model. Agent logic is built with the Strands Agents SDK, an open source framework for building AI agents with tool use. The system coordinates specialized agents through a composer that routes each request to the right specialist, so each agent handles a focused task and can be evaluated and improved independently. The team chose these managed services over building the agent runtime and model access in-house. Amazon Bedrock provides access to leading foundation models through a single API, giving the team flexibility to adopt newly introduced models without managing separate endpoints. Amazon Bedrock AgentCore provides a managed agent runtime that removes the operational overhead of running agents in production.

It has been revealed that figure 1 highlights this flow in implementation terms. A user request enters through LoanPro API v2 on Amazon API Gateway. An AWS Lambda handler places the request on an Amazon Simple Queue Service (Amazon SQS) queue. The Agent Interceptor Lambda function then invokes the Loan Summary Agent. The agent runs on Amazon Bedrock AgentCore runtime, a capability of Amazon Bedrock AgentCore, and uses Anthropic’s Claude models on Amazon Bedrock. It reaches its tools through a Model Context Protocol (MCP) server on Amazon Bedrock AgentCore Gateway, a capability of Amazon Bedrock AgentCore. The gateway finds the right tool in a catalog that the Loan Summary Service registers in AWS Systems Manager Parameter Store. The Loan Summary Tool Lambda function validates the caller’s signature against LoanPro’s single sign-on (SSO) service. It then retrieves account data from LoanPro’s loan management system, which runs on Amazon Elastic Compute Cloud (Amazon EC2) behind a Network Load Balancer. The system’s role-based access controls validate the same signature. LoanPro also checks each request against the user’s permissions and compliance controls, then writes the action to its audit trail. The sections that follow describe these pieces: the multi-agent system, the tools it calls, and the gateway.

The architecture has four key components, which combine the pieces in Figure 1 with the composer agent and Invoke API Tool that coordinate and act on them:.

The solution uses a multi-agent architecture built with the Strands Agents SDK. Rather than a single monolithic model handling every task, specialized agents collaborate to serve different parts of the servicing workflow. One agent focuses on data retrieval and account summarization. Another handles action selection and workflow recommendations. A composer agent routes each request to the right specialist and composes the final response. This separation of concerns makes each agent more straightforward to evaluate, tune, and extend independently.

Industry observers note that the agents retrieve borrower data from LoanPro’s internal systems through tool use, a capability in Amazon Bedrock for calling external functions and APIs. Two primary tools power the assistant:.

By connecting to LoanPro’s existing APIs, the assistant works with live production data without requiring a separate data pipeline or data warehouse.

AgentCore Gateway is the secure access layer between the agents and the tools they call. It exposes LoanPro’s APIs to the agents as tools over the Model Context Protocol (MCP), handles authentication, and manages those connections. AWS Lambda, a serverless compute service that runs code without provisioning or managing servers, provides the integration layer between the gateway and LoanPro’s APIs. The team chose AgentCore Gateway with Lambda over a direct integration for three reasons. It centralizes authentication at a managed entry point, isolates LoanPro’s APIs behind a managed boundary, and lets new tools be added without redeploying the agents. This serverless approach keeps the infrastructure lightweight and scales automatically with request volume. In Figure 1, the Agent Interceptor (an AWS Lambda function) invokes the agent on AgentCore runtime. AgentCore Gateway enforces this access control, screening each request before it reaches the Loan Summary Tool. Because the assistant operates in a regulated lending context, the production deployment pairs these components with additional controls. LoanPro’s role-based access controls and compliance guardrails apply to each request, and AI actions are written to LoanPro’s audit trail and attributed to a named, responsible person.

In a recent development, loanPro had an existing proof of concept (POC) that used a large language model (LLM) to convert natural language into rule automation code for their Clojure rules engine. The core functionality worked, but the solution had known limitations: frequent timeouts, no monitoring, and no deployment strategy. AllCloud conducted architectural reviews and provided recommendations to bring this existing POC to a production-ready state, including a documented production architecture and risk assessment.

Sources indicate that A structured evaluation pipeline validated agent accuracy against benchmarks established by LoanPro’s subject-matter experts (SMEs). The team assembled a benchmark of 150 SME-labeled accounts. Against that benchmark, they measured the agent’s ability to retrieve data, summarize findings, and select appropriate actions, holding it to a 99 percent accuracy target that the agent met. This framework carries forward into production, giving LoanPro a repeatable process for measuring and improving agent performance over time.
