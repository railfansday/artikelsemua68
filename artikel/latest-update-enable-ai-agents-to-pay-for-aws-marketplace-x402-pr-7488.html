In a recent development, when Amazon Bedrock AgentCore payments became generally available in August 2026, agents could autonomously pay for paid APIs, MCP servers, and web content over open protocols like x402 and MPP with payment limits and full observability. Today we extend that autonomy to AWS Marketplace, so agents can discover and buy x402-enabled software, APIs, data, and content, and pay in USD on the agent developer’s AWS bill, removing the need for stablecoin wallets or API keys.

Figure 1: Overview of AgentCore payments showing the newly introduced AWS Billing integration for purchasing on AWS Marketplace.

Developers can also configure and automate discovery through the AWS Marketplace connector in AgentCore Gateway. Existing guardrails carry over, developers can set spending limits and approved sellers using AgentCore policy, and the payment session cap is enforced by AgentCore payments, so an agent is unable to overspend. Transactions are auditable in AWS CloudTrail and AWS Cost Explorer. Because agent purchases run through AWS accounts on both sides, agentic purchasing meets the security and auditability enterprises expect.

Sources indicate that today’s launch adds AWS Billing as a payment option in AgentCore payments. An agent can now pay x402-enabled AWS Marketplace sellers per request, in USD, settling on their AWS bill.

When an AWS Marketplace seller responds with 402 Payment Required, its response includes a signed quote for the purchase. With AWS Billing, the agent can forward the seller’s x402 response to AgentCore payments. AgentCore payments checks session budgets, then returns a payment token. The agent retries the request to the seller with the payment token included and receives a successful response. AWS bills the charge to the AWS account where Payment Manager is set up, and the charge appears on that account’s AWS bill.

Industry observers note that to set up AWS Marketplace purchasing, the developer creates a Payment Manager with an AWS Billing connector. The connector only requires you to set up a service-linked role to access AWS Marketplace. Then, for each task, developers can create a payment session with a spending limit and give the agent the session ID.

Sources indicate that an agent’s first purchase from a seller creates an agreement for the AWS account with that seller, and AWS Marketplace automatically tracks later purchases against it. Each product will then show up as an AWS Marketplace line item. If your organization uses Private Marketplace, agents can only buy the products it allows.

In a recent development, in addition, to discover new sellers, we are launching a new AWS Marketplace connector in AgentCore Gateway. This optional integration helps agents find products and their endpoints. At launch, AWS Billing supports the x402 exact scheme, where the seller quotes a fixed price for each request.

According to recent reports, in this post, we walk through a research agent that discovers a tool, pays for a single request through AWS Billing, and answers with sources, with nothing set up in advance. We also provide an accompanying GitHub sample that you can use to evaluate the setup in your own AWS account.

Suppose a financial analyst asks the agent what was unveiled about agentic payments this week. The model wasn’t trained on this week’s news, so the agent looks for a search tool. Through AgentCore Gateway, it searches AWS Marketplace, reads the listing from Tavily, an AWS Marketplace seller, and requests the listing’s x402 endpoints.

In a recent development, the agent calls the endpoint and receives an x402 payload with price details. The agent then forwards the x402 payload to AgentCore payments. AgentCore payments checks it against the remaining session budget and returns a payment token. Once these checks are passed, the agent sends the request again with the token attached, and gets the search results. Its answer includes sources and states what it bought and what it cost.

In this workflow, agents can apply their reasoning to decide which AWS Marketplace tool to use.

Figure 2: End-to-end flow of the sample solution using a Strands agent.

1. Discover. The agent calls three read-only gateway tools in order: search listings, get a listing, and list its fulfillment options. Search listings tool only returns endpoints that accept x402. The last call returns the seller’s endpoint URL and the payment protocols it accepts.

It has been revealed that 2. Get a quote. The agent calls the endpoint with no payment attached. The seller answers with HTTP 402 and puts a signed quote in the PAYMENT-REQUIRED header. AWS Marketplace checks the signature against the seller’s registered key, which means a quote with an altered price gets rejected.

3. Pay. The agent passes the quote to the ProcessPayment API with the payment type AWS_BILLING_X402. If budget remains in the session, AgentCore payments issues a payment token. If not, the call fails and the developer is not charged.

4. Redeem. The agent sends the request again, this time with the token in the PAYMENT-SIGNATURE header, and the seller returns the content. Payment tokens are valid for about five minutes, so the agent completes steps 2 through 4 in a single pass.

5. Settle. On the developer’s first purchase from a seller, AWS Marketplace creates the agreement with that seller. After that it meters each charge to their AWS bill. Settlement runs asynchronously and demonstrates up in their AWS bill monthly.

Industry observers note that to create an AWS Billing connector, developers’ AWS accounts must have the AWS Marketplace service-linked role AWSServiceRoleForMarketplaceAgenticCommerce. AWS Marketplace uses this role to bill AWS Marketplace purchases that their agents make to their AWS account. Refer to the documentation for more details.

The open-source GitHub sample in the agentcore-samples repository runs through a demo of the newly introduced functionality. It can help you configure AgentCore payments for AWS Marketplace, connect Tavily, run the agent, and inspect the transaction. You can refer to the documentation for more details.

setup_aws_billing.py creates a payment manager with an AWS Billing connector, plus the AWS Marketplace service-linked role and three separate AWS Identity and Access Management (IAM) roles. The session role can set budgets but can’t pay. Meanwhile the agent role can pay but can’t create sessions, so the agent has no way to raise its own budget.

Recent findings suggest that setup_gateway.py creates an AgentCore Gateway with the AWS Marketplace connector and gives the agent role the appropriate permissions to use it. The gateway’s role is limited to three read-only AWS Marketplace actions. If you choose to skip this step, you can instead set SELLER_URL in the environment variables to the seller’s endpoint, and the agent will pay that URL only rather than using AgentCore Gateway discovery.

It has been revealed that the script creates a payment session as the session role and then runs the agent as the agent role. By default the session budget is $0.05 and the per-request cap is $0.02.

According to recent reports, the agent searches, looks at listings, gets an endpoint, and pays once. In this test run against a $0.01 seller, it compared two listings before buying:.

Recent findings suggest that when the run finishes, the sample will print the payment with its amount, AWS Marketplace product ID, and processPaymentId. The AWS Marketplace meters charges asynchronously, so the Tavily line item takes a moment to appear on your bill. Agent purchases will also show up in AWS CloudTrail and AWS Cost Explorer.

According to recent reports, run cleanup.py to delete resources. Make sure to validate deletion to avoid incurring additional resource charges.

AgentCore payments and AWS Marketplace provide the infrastructure for agents that can transact. The research agent in this post goes from “I need live web search” to sourcing an answer on its own, discovering premium paid content through tools, and paying for requests that settle on the developer’s AWS bill.

Sources indicate that with AgentCore payments, developers can build with open protocols like x402, which opens them to a growing catalog of trusted, verified AWS Marketplace sellers. This gives agents more autonomy and developers more control. Governance is built in, with per-session spending caps and an approved seller list using AgentCore policy, and IAM identities that make it auditable in AWS CloudTrail and AWS Cost Explorer. The agent chooses the right tool for the task, and developers can keep the same billing, budgets, and controls they already trust.
