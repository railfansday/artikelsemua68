In a recent development, the 2026 winning agent offers lessons that go well beyond the game. Each design choice maps to a decision teams face when they run agents in production.

The agentic AI challenge scores agents on challenge points, a treasure bonus, remaining lives, and a token bonus, computed as tokenBonus = 1000 - (totalOutputTokens / challengesVisited).

According to recent reports, in the qualifier, the top four agents all solved the map. The first-place agent emitted 1,220 output tokens and the second-place agent emitted 1,430, and the final margin was only 16 points out of nearly 16,000. After every agent can solve the problem, efficiency decides the winner.

Recent findings suggest that to understand which tokens mattered, Nishanth built nine variants of the same agent, changing one thing at a time. The result was clear: tool results and the system prompt didn’t count against the score, but everything the agent wrote, including tool call arguments, did. Each tool call carried roughly 52 tokens of fixed overhead on top of its arguments.

This mirrors real-world cost. Generating output is sequential and is typically priced several times higher than input, and in an agent loop that cost compounds across every step. A long, well-structured system prompt (which you can also cache) is cheap. A chatty agent isn’t.

A common architecture for this challenge is a supervisor agent on Amazon Bedrock AgentCore that delegates to specialist sub-agents for navigation, computation, and web retrieval. It’s a sound pattern for many production systems. The winning design used a single agent with no sub-agents. Instead, the prompt began with a short dispatch table that matched each challenge type to the right approach in a single turn.

Recent findings suggest that the reasoning was simple: every handoff between agents is a message the model has to write, and in this challenge every written token is scored. The lesson isn’t that sub-agents are bad. It’s to choose your architecture based on what coordination costs you. When coordination is expensive, a flatter design can win.

According to recent reports, the following diagram shows the AWS reference architecture for the agentic AI challenge: a supervisor agent with specialist sub-agents. The winning design deliberately didn’t use this multi-agent pattern.

Figure 5: AWS AI League reference architecture.

In this reference architecture, a supervisor agent runs in Amazon Bedrock AgentCore runtime, a capability of Amazon Bedrock AgentCore, and coordinates three sub-agents, with Amazon Bedrock Guardrails and AgentCore memory connected to the runtime. The supervisor and sub-agents route through the Amazon Bedrock AgentCore Gateway, a capability of Amazon Bedrock AgentCore, to four tools: a navigation tool, browser tool, code execution tool, and custom tools using AWS Lambda functions.

It has been revealed that route planning was not left to the model. It ran in an AWS Lambda function that treated the board as an optimization problem. Each tile carried an expected value: the points it paid, minus the lives it could cost, minus the tokens the agent would spend to solve it. The planner respected constraints, such as collecting a key before its door, and refined the route within a time budget.

This is a useful pattern for most agents: let the model handle language and judgment, and move search, math, and rules into tools where they are faster, cheaper, and repeatable.

It has been revealed that the second finale round was designed as a trap. A seven-by-seven board was almost entirely covered in coins worth 25 points each, while a single scheduling challenge tile was worth 1,500 points. Habit said to collect the coins. The planner’s value table said the coins were noise. The agent went for the high-value challenge and scored 7,537 points in that round, compared with 5,953 for the next finalist. That round built the lead that carried the agent to the overall win.
