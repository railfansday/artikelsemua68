Entertainment marketing teams manage tens of thousands of video assets across studios, networks, and streaming applications. Most campaigns begin with the same video discovery problem: finding the one moment in the footage that will resonate with an audience. When a brief lands, the clock starts, and what they need is almost never something a database can describe.

Semantic search, on its own, has a ceiling: It answers the question you can articulate. Ask it for a character holding a coffee mug and it will find every coffee mug in a thousand episodes. The queries that actually drive entertainment campaigns look nothing like that. They are questions of judgment: which moment in a show will travel, which line is quotable, and which single frame will work as a meme.

Recent findings suggest that those questions can’t be typed into a search box. Answering them requires two things the search index doesn’t have: an editorial definition of what “quotable” or “memeable” means for a given library, and a continuously refreshed view of what is moving outside the library. Historically, answering them meant a person with deep knowledge of the show watching footage for a week, and that person doesn’t scale across a catalog.

According to recent reports, in this post, we describe how Social Department, the AI operating system for entertainment marketing, set out to encode those editorial questions as executable retrieval pipelines. The result is QuickSearch, a set of single-action queries that return the clips a marketer is looking for without requiring them to describe it: Shareable Scenes, Quotable Quotes, Memeable Moments, and Trend Align.

The models in this solution run on Amazon Bedrock, so customer data stays within the AWS data boundary. It isn’t shared with model providers and isn’t used to train the underlying models.

Industry observers note that social Department’s approach to responsible AI is that AI proposes and people decide. In production, code checks generated output against the source material (for example, a quote is discarded if it isn’t in the episode transcript). Amazon Bedrock Guardrails helps screen customer search text for prompt attacks, and a person on the customer’s team approves every post before it publishes.

It has been revealed that social Department owns the pipeline architecture, the retrieval system, and the editorial criteria behind each action. TrackIt, an AWS Premier Tier Services Partner, implemented and delivered against that design. TwelveLabs’ Marengo 3.0 and Pegasus 1.2 models on Amazon Bedrock provide the scene-level video reasoning the pipeline builds on. AWS supplies the infrastructure, the model access including Anthropic’s Claude models, and Amazon OpenSearch Service, using its serverless option, Amazon OpenSearch Serverless, for retrieval.

Industry observers note that social Department is the AI operating system for entertainment marketing, serving major studios, networks, streamers, and FAST applications. It automates campaign strategy, asset creation, publishing, and performance optimization across a client’s full content library. Most of those functions depend on locating the right moment inside the footage first, and semantic clip discovery has been core to the product from the beginning.

Entertainment marketing operates under two constraints that a general-purpose search layer can’t satisfy.

According to recent reports, A marketer can describe an object, a location, or a line of dialogue, but not what will travel. That judgment, this moment lands and that one doesn’t, is the actual skill in the job. It was never automatable because it depends on knowing how an audience behaves rather than what a video contains. A search layer that only understands content requires a human to supply the intent, and supplying that intent well requires having already watched the show.

According to recent reports, no amount of video understanding tells you what audiences are talking about this morning. That information is created outside the library and changes hourly, while a library changes only when newly introduced content is added. A system that answers these queries has to acquire trend signal continuously and reconcile it against the library at request time.

That distinction drove the core architectural decision: content understanding and trend acquisition run as independent pipelines on their own schedules and are joined only when a user selects a QuickSearch action.

According to recent reports, with QuickSearch, teams can interact with a video library in a different way, one where the system proposes rather than waits. It provides four actions, each with its own retrieval strategy, editorial criteria, and ranking model. The walkthrough that follows describes how each is implemented. The list here introduces what they do.

Alongside these, Social Department keeps natural-language search for everything the actions don’t cover, and image-based search, where a reference image returns visually similar content across the library.

It has been revealed that this pipeline makes the library legible. It works asynchronously on ingest. An AWS Step Functions state machine orchestrates roughly two dozen Python AWS Lambda functions end to end. The following steps trace one video from upload to indexed clips.

The pipeline is event-driven end to end. Every Lambda task retries with exponential backoff. The scene-description stage adds a dedicated throttling retry with full jitter. Non-critical enrichment steps degrade gracefully rather than failing the run, and a hard failure routes to an error handler that records the reason and reports the asset as failed.

In a recent development, same-Region staging for Marengo. Marengo is available in a specific set of AWS Regions. Asynchronous invocation in Amazon Bedrock reads input from and writes output to an Amazon S3 bucket in the same Region as the endpoint. The pipeline is built around those parameters. It stages each video into a dedicated bucket in US East (N. Virginia) before invoking Marengo, then reads the embedding output back from the same bucket. The rest of the infrastructure stays in its home Region while each embedding job runs alongside the model. For model availability by Region, see Model support by AWS Region in Amazon Bedrock.

This pipeline operates continuously and independently of any library, and it is what makes Trend Align possible.

It has been revealed that quotable Quotes draws on a second, narrower input: an external dialogue popularity signal, used strictly to weight lines that have already circulated. It’s optional by design, so if the signal is unavailable a line gets no boost rather than failing the job.

It has been revealed that this layer is where a single selection becomes a retrieval strategy. It executes each action asynchronously and returns a ranked set of clips.

Three choices made culturally informed retrieval tractable.

Industry observers note that A library changes when newly introduced content is added. Trends change daily, and early-stage trends faster than that. Coupling the two would mean either reprocessing content against fresh signal, which is computationally untenable, or serving stale trend judgment. Keeping them as independent pipelines joined at request time means signal stays current without the library ever being touched again. A title that finished airing years ago can re-enter a live conversation.

The naive design puts one large model in front of the whole library. QuickSearch instead uses inexpensive, high-recall vector and keyword retrieval to build a candidate pool, then spends model budget only on ranking a capped set of real candidates. The caps are sized against the ranking model’s output token limit, because a ranker that truncates mid-response silently drops results. This also keeps the per-query cost of Amazon Bedrock predictable: one embedding call, one rerank call, and a small fixed number of Claude invocations, regardless of library size.

Recent findings suggest that results are cached for 30 days. Without intervention, a change to an action’s criteria or model would stay invisible to people until the cache expired. Each action carries a pipeline version that is bumped in the same change that alters its behavior. That bump invalidates prior results immediately, so editorial judgment is refined as a versioned change to the product rather than relitigated on every query.

The following four lessons from the project stood out.

Retrieval is largely solved. What isn’t solved is specifying intent precisely enough for retrieval to be useful without an expert marketer in the loop. Most of the engineering effort went into defining what qualifies as a shareable scene or a memeable frame, tightly enough to execute repeatedly across libraries with different tones and audiences. That definition is the output of a standing evaluation program of numbered iterations, each measured against per-show ground-truth sets and a tracked baseline, that tunes the criteria against results rather than intuition.

It has been revealed that quickSearch uses a multi-model architecture, with each model assigned to the work it fits best. Claude Haiku handles bounded, cost-sensitive output, and Claude Sonnet handles tasks where cultural recall changes the answer. TwelveLabs Marengo produces multimodal embeddings, TwelveLabs Pegasus provides scene-level video reasoning, and the Amazon Rerank model handles reranking. Amazon Bedrock made this architecture practical to build and run. Models from TwelveLabs, Anthropic, and Amazon are available through one API, so Social Department can change the model behind a task when measured quality moves, without building a new integration. Asynchronous invocation runs long video embedding jobs at library scale, and the Rerank API adds a relevance pass without separately hosted infrastructure. Amazon Bedrock Guardrails helps screen search input in the same service, and customer data stays within the AWS data boundary. Because Amazon Bedrock is fully managed, the team operates no model-serving infrastructure of its own.

In a recent development, treating trend data as another input to the content pipeline would have failed, because the two have incompatible lifecycles. Recognizing early that library content and live culture are separate systems, with separate refresh rates, storage, and failure modes, was the decision the rest of the design depended on.

Several AWS components make up the layer this post describes. TwelveLabs Marengo handles multimodal embedding and TwelveLabs Pegasus handles scene-level video reasoning, both on Amazon Bedrock. Anthropic’s Claude models on Amazon Bedrock handle interpretation and editorial ranking, and Amazon OpenSearch Serverless handles hybrid retrieval. AWS Step Functions, AWS Lambda, AWS Elemental MediaConvert, Amazon Rekognition, Amazon DynamoDB, and Amazon SQS run the pipelines around them. The result is a set of single-action queries that return the clips audiences already care about, the lines they already quote, the frames that will work as memes, and the moments that connect to whatever is trending right now.
