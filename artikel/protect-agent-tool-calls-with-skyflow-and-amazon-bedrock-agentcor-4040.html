In a recent development, in this post, we show how Skyflow and Amazon Bedrock AgentCore Gateway keep sensitive data out of the tools your AI agents call, and out of the model context those tools feed. We add Skyflow Detect to Amazon Bedrock AgentCore Gateway as a request and response interceptor. The Skyflow interceptor de-identifies data before it reaches a tool, restores it before the agent reads the result, and replaces documents with clean copies before the agent opens them. Your agents and tools don’t change.

Skyflow is available in AWS Marketplace, and the interceptor is open source on GitHub.

Recent findings suggest that agents have moved from answering questions to taking action, and they take action through tools: Model Context Protocol (MCP) servers, SaaS APIs, document stores, and web search. Every agent tool call is a data flow. Most enterprise controls cover what goes into and comes out of the model. Far fewer cover what an agent sends to its tools or what those tools send back.

That gap reveals up in three ways:.

Sources indicate that patching each agent doesn’t scale across teams and frameworks, and it can’t reach third-party tools. The controls need to sit where every tool call passes, so authorization, content safety, and data protection apply the same way to every agent and tool.

AgentCore Gateway is that place. It fronts every tool an agent uses, whatever framework or model the agent runs on. It does more than route that traffic. With AgentCore Gateway interceptors, you can run your own code, as an AWS Lambda function, on every call that passes through it. A request interceptor sees each call before it reaches a tool, and a response interceptor sees each result before it reaches the agent. Either one can inspect the payload, rewrite it, or block the call. That makes the gateway a natural place to add data protection alongside Policy and Guardrails. This single control, attached once, covers every agent and every tool behind the gateway, without any change to agent or tool code.

With the Skyflow interceptor on the gateway, the same workflow plays out differently:.

The Skyflow interceptor is a single AWS Lambda function attached to both of the AgentCore Gateway interception points:.

It has been revealed that at each point, it calls Skyflow Detect to find sensitive entities such as names, email addresses, phone numbers, government IDs, card numbers, dates of birth, and locations. It replaces them with tokens, or restores the originals. Skyflow Vault stores the original values so authorized systems can reverse the tokens.

The Skyflow gateway configuration decides, for each tool, which of three protection modes applies: Shield the tool, Shield the model, and Shield the document.

In a recent development, the agent runs on AgentCore runtime, a capability of Amazon Bedrock AgentCore. Alongside that flow, the interceptor reads its policy from Parameter Store and its Skyflow API key from Secrets Manager, and it logs each decision to Amazon CloudWatch. It calls Skyflow Detect and Skyflow Vault in an approved Region to de-identify and re-identify data. The targets sit outside the gateway: a third-party web search MCP server, a case-note store in Amazon S3, and a model in Amazon Bedrock that the gateway reaches through an inference target. For model calls, the interceptor keeps a short-lived record in Amazon DynamoDB of which tokens each call minted, so it restores only those. The record holds no original values. For documents, Skyflow Detect fetches the file directly through a presigned URL, so the file bytes never pass through Lambda.
