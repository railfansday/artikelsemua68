Industry observers note that with retrieval instructions in Amazon Bedrock Managed Knowledge Base, you can customize answers per tenant. The same product and policy documents often serve several audiences, such as customers in different regions or internal teams, and each audience needs its own answer. You set the voice, format, retrieval guidance, and answer policy that agentic retrieval applies to each request. Before this feature, you couldn’t set the answer style, so agentic retrieval could use a different style from one request to the next. For a fixed voice or structured output, you had to turn off response generation, call a model yourself, and maintain the prompt in every application.

Now you write that guidance once, as a managed, versioned Amazon Bedrock resource, and each request references it. When you change an instruction, you can pin a version so that each application switches to the latest version when you’re ready.

Take AnyCompany Smart Home, a fictitious company that sells a home controller and room sensors in three sales regions. Its customer assistant serves all three regions, and its support, field sales, and legal teams use internal assistants that they built on the same documents. AnyCompany defines each region and internal team as a tenant here, and each needs a different answer. A customer in Sales Region Central needs Spanish with day/month/year dates, and a support agent needs a short ticket note. To keep the example compact, every tenant queries one knowledge base. However, agentic retrieval can search up to five knowledge bases in a single request, and the tenant’s instruction applies to all of them.

Sources indicate that retrieval instructions change how the assistant answers, but they aren’t an authorization or data-isolation boundary. Use metadata filters or separate knowledge bases to control what each tenant can retrieve. In this post, we show how to give each tenant its own answers from shared knowledge bases while keeping each tenant’s data separate. By the end, you can roll out a change to one tenant’s instruction and confirm which version answered each request.

According to recent reports, A metadata filter keeps one knowledge base to sync and maintain, but every document needs accurate metadata, and your backend must build the filter correctly on every request. Industry observers note that with a tenant filter or a separate knowledge base, the agent retrieves only documents the tenant is entitled to, so answers don’t quote other regions’ values. An answer policy that limits the assistant to one region helps, but without a filter an answer can still quote another region’s value.
